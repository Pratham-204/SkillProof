# Self-extending taxonomy publishes without human review, gated by deterministic + LLM checks

CONTEXT.md's Notes originally deferred a self-extending taxonomy with an explicit "human-approved before entering the scored path" gate. We decided to drop that gate entirely: a nightly batch job evaluates Sightings (unrecognized manifest packages, seen across a minimum number of distinct Candidates) and publishes new Skill Tags directly, with no human in the loop. In its place, publishing requires the sighted package to actually exist on its ecosystem's real registry, to be neither an exact/case-insensitive nor an LLM-judged semantic duplicate of an existing entry, and for the LLM to not have abstained (it may decline any Sighting it doesn't judge to be a genuine claimable skill) — the same LLM is also constrained to the taxonomy's existing five categories, never allowed to mint new ones. We chose automation over a bespoke review workflow because SkillProof has no authenticated actor besides Candidate today, and standing up an Admin role and review UI just for taxonomy review would be a much larger scope increase than the feature itself.

## Consequences

A bad entry can go live before anyone notices; recovery is the same manual `skills.json` edit and version bump used for any hand-curated correction, not a dedicated retraction flow. Because `taxonomy_version` is a single global counter (ADR-0005), publishing is batched onto a fixed cadence rather than continuously, specifically to bound how often unrelated Evidence Cards get forked by a taxonomy change they have nothing to do with.
