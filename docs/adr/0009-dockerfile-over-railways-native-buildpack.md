# Production builds from a checked-in Dockerfile, not Railway's native Railpack/Nixpacks buildpack

Railway can build a service two ways: auto-detect a language/framework and build it with its own buildpack (Railpack, formerly Nixpacks), or build from a Dockerfile in the repo. We chose the Dockerfile explicitly rather than leaving the service on auto-detect. Railpack's Python auto-detection only recognizes a small, fixed set of shapes — FastHTML, FastAPI's own conventions, Flask, Django, or a bare `main.py`/`app.py` in the project root — and has no way to know that this repo's actual entrypoint is `skillproof.main:app` inside a `src/` layout, or that the single-origin app (ADR-0006) needs a Node build step for `frontend/dist` before the Python process ever starts. A multi-stage Dockerfile (a Node stage building the frontend, a Python stage running the backend) states both of those steps explicitly instead of hoping a generic buildpack infers them.

This was proven, not assumed: with the service left on auto-detect during ticket 05's live verification, Railway's build failed with `No start command detected`, and a bot subsequently opened a PR against this repo proposing a `railway.json` with `"builder": "RAILPACK"` and a guessed `uvicorn src.skillproof.main:app` start command — which would have bypassed the Dockerfile (and its frontend build stage) entirely had it been merged. Pointing the service's Builder setting at the checked-in `Dockerfile` instead resolved the failure without needing any such workaround.

## Consequences

The Dockerfile is now a second place (alongside `pyproject.toml` and `frontend/package.json`) that has to be kept in sync with how the app actually builds and runs — a dependency or entrypoint change needs updating there too, where a pure-buildpack setup would infer it automatically. In exchange, the build is fully reproducible outside Railway (`docker build` runs identically on any machine) and CI can verify it directly (ticket 02's build-and-boot smoke test), neither of which a buildpack-only setup provides.
