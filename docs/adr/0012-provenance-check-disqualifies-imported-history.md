# Provenance Check disqualifies commits from repos with imported history

ADR-0004's anti-gaming corrections close two specific gaps — forking a large repo to inflate Volume, and writing an elaborate commit message to inflate Depth — but leave a third open: nothing stops a Candidate from importing another project's real git history into their own, non-forked, owned repo and relabeling its authorship as their own. Because Volume for owned repos already trusts `author = candidate` at face value (ADR-0004), a rewritten or imported history with spoofed authorship passes that filter cleanly. We decided to add a Provenance Check: for each owned, non-forked repo already in the current Evidence Bundle, one GitHub commit-search API call checks whether that repo's earliest commit's SHA already exists in another public repo the Candidate doesn't own. A match hard-disqualifies that repo's commits from Volume, Depth, and Span — not Presence, since a manifest declaration carries no authorship claim to dispute.

## Consequences

The check is scoped to a single call per owned repo (checking only the earliest commit, not the full history), keeping cost bounded and compatible with `/verify`'s existing in-process, no-queue execution model (round 3). It intentionally does not use commit-date heuristics (e.g. "first commit predates account creation") — that signal has a common, entirely legitimate innocent explanation (a Candidate coding locally for years before creating a GitHub account) and doesn't actually test authorship, only timing, so it was rejected in favor of a SHA match, which is high-precision because two different commits practically never share a hash by coincidence. A positive match is cached permanently once found; a clean result is re-checked on every future `/verify` rather than cached, since a clean result today doesn't guarantee one tomorrow. The check is deliberately silent — a match changes the resulting Confidence Score but is never surfaced as a visible flag on the Evidence Card, since that page is public and unauthenticated with no dispute mechanism designed yet; a visible fraud-adjacent label is a separate, later decision. A Candidate who legitimately imports their own already-merged, PR-based external contribution into a personal repo will trigger this check, but loses nothing — that contribution already counts via ADR-0004's external-repo PR-membership path, so disqualifying the duplicate only prevents double-counting the same real evidence.

## Considered Options

Commit-date anomaly heuristic (first commit date vs. account creation date) — rejected: high false-positive rate against a common, entirely legitimate scenario, and doesn't test authorship at all, only timing.

Full cross-repo hash comparison across every commit, not just the earliest — deferred, not rejected: meaningfully more expensive (potentially one API call per commit rather than per repo) and better scoped as its own follow-up once the cheap, single-commit check has proven the concept in practice.
