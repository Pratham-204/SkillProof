# 02 — Span Ceiling: cap confidence score for unsustained bursts

**What to build:** Close the scoring-shape gap where a short, intense burst of Volume/Depth evidence can reach a high Confidence Score discounted by no more than Span's 15% weight. Add a Span Ceiling: a separate multiplicative factor on the final Confidence Score, distinct from and layered on top of the existing four-Signal weighted sum.

**Blocked by:** none (applies to `scoring.py`'s existing `score_skill`, independent of issue 01)

**Status:** done

- [x] Add a new named constant for the Ceiling's saturation curve (e.g. `SPAN_CEILING_SATURATION_DAYS`), distinct from and larger than `SPAN_SATURATION_DAYS` — do not reuse or rename the existing constant.
- [x] After the existing `confidence_score = PRESENCE_WEIGHT * presence + VOLUME_WEIGHT * volume + DEPTH_WEIGHT * depth + SPAN_WEIGHT * span` computation and its `[0,1]` clamp, apply a smooth saturating multiplier derived from `span_days` and the new constant (mirroring the shape of the existing `n/(n+k)` saturation curves already used for Volume and Span — not a hard cutoff/step function).
- [x] `PRESENCE_WEIGHT`, `VOLUME_WEIGHT`, `DEPTH_WEIGHT`, `SPAN_WEIGHT`, and their 0.20/0.40/0.25/0.15 values (ADR-0004) are unchanged by this work — the Ceiling is a final adjustment, not a fifth Signal, and does not touch the weighted-sum formula itself.
- [x] A fixture demonstrates the effect: two fixtures with identical Presence/Volume/Depth inputs but different `span_days` (one short-burst, one long-sustained) produce different final `confidence_score` values despite an identical pre-Ceiling weighted sum.
- [x] A fixture demonstrates the floor case: a Candidate with zero qualifying evidence (`span_days = 0`) still produces `confidence_score = 0`, not a divide-by-zero or other edge-case failure in the Ceiling's saturation formula.

## Comments

Implemented in `scoring.py`: new `SPAN_CEILING_SATURATION_DAYS = 365` constant, and `confidence_score *= span_days / (span_days + SPAN_CEILING_SATURATION_DAYS)` applied right after the existing weighted-sum `[0,1]` clamp. `score_skill`'s docstring updated to mention it.

New tests in `test_scoring.py`: `test_span_ceiling_widens_the_gap_between_a_burst_and_sustained_activity_beyond_spans_own_weight` (5 identical qualifying commits, 3-day vs. 400-day spread — proves the post-Ceiling gap exceeds what Span's own 0.15 weight alone could ever produce) and `test_span_ceiling_zeroes_the_score_when_there_is_no_qualifying_evidence` (real Presence + Volume, no Depth-qualifying item, `span_days = 0` → `confidence_score == 0.0`, no exception).

**Note on bullet 4's literal wording:** "an identical pre-Ceiling weighted sum" between a short-burst and long-sustained fixture is mathematically impossible once `span_days` differs, since Span's own `SPAN_WEIGHT`-weighted term is itself a function of `span_days` and moves too — a fixed point flagged this during `/code-review`'s Spec pass. `test_span_ceiling_widens_the_gap_...` substitutes the strongest available faithful reading instead: it proves the *actual* post-Ceiling gap between the two fixtures exceeds `SPAN_WEIGHT * (span(400) - span(3))` — i.e. exceeds the maximum gap Span's own weighted slot alone could ever produce — which is the concrete claim the ticket's opening paragraph makes ("discounted by no more than Span's 15% weight").

**Scope decision surfaced mid-implementation and confirmed with the user:** applying the Ceiling literally (uniformly, derived only from `span_days`) also zeroes every `declared_only` score, since a `declared_only` card by definition has zero qualifying (Depth/Span) evidence and therefore `span_days = 0` always. This directly narrows round 6/ADR-0004's "declared-only produces a small nonzero score, not zero" guarantee — `declared_only` and `none` are no longer distinguishable by `confidence_score`, only by `evidence_type`. Confirmed this is the intended behavior (not a carve-out for zero-Volume cases) rather than silently deviating from the ticket's literal floor-case requirement. Updated `CONTEXT.md`'s Declared-Only term and the round 11 note to state this explicitly, and fixed 3 pre-existing end-to-end tests in `test_api_flow.py` that asserted the old nonzero `declared_only` score (`test_search_and_semantics_requires_every_selected_skill`, `test_verify_produces_declared_only_for_a_manifest_dependency_never_touched`, `test_verify_excludes_flagged_owned_repo_commits_but_keeps_its_declared_presence`). Also updated two existing `test_scoring.py` tests whose asserted `confidence_score` predated the Ceiling and one whose fixture dates coincided (span_days=0), which would otherwise have masked the Depth-discount math it was pinning.

Full suite: 150 passed, mypy clean (`src` + `tests`).

**Follow-up, surfaced by a live `/verify` run against real data:** the raw Ceiling crushed genuine single-qualifying-commit evidence (the common case for a normal-sized repo — one commit's date has no range, so `span_days = 0` exactly like the true no-evidence case) to a literal 0.0 Confidence Score, reading as "no evidence" on the Evidence Card when real, decent-similarity evidence existed. Added `SPAN_CEILING_FLOOR = 0.1`: floors (doesn't zero) the multiplier whenever `qualifying` is nonempty, leaving the true zero-qualifying-evidence floor case (this ticket's bullet 5) untouched and still exactly 0. New test `test_span_ceiling_floors_rather_than_zeroes_a_single_qualifying_commit`; `test_span_ceiling_zeroes_the_score_when_there_is_no_qualifying_evidence` (bullet 5's fixture) still passes unchanged, since its scenario has zero qualifying items, not one. Updated ADR-0013 and CONTEXT.md accordingly. Full suite re-run: 152 passed, mypy clean.
